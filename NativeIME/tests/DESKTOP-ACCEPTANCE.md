# Experimental desktop acceptance (NOT_RUN)
Use a disposable Windows 11 VM, x64. No default IME change. Build experimental TSF and Rime service, place DLL and EXE in the same protected test directory. Start EngineService explicitly with isolated shared/user data paths. Register the experimental DLL only inside the VM and select NativeIME manually. In a standard Win32 Edit control type nihao, wait for visible candidates, select 你好, verify exact committed text; repeat with digits, backspace, Esc, Ctrl+S, password/readonly, focus loss, rapid typing, service termination and restart. Capture actual screenshots and record latency. Unregister after test. No claim of live TSF compatibility from COM smoke or IPC tests. Image path comparison is not signature verification; release requires protected installation and code integrity review.

Use NativeIME.DesktopLab.exe as the ordinary native EDIT host. It does not intercept typing or emulate an IME. The CI native-control integration uses EM_REPLACESEL rather than an actual TSF edit session and is separately classified; only actual profile activation and typing can satisfy TEST-TSF-002. Do not alter the default profile or register on a daily-use machine. Record screenshot and actual text from the normal field, verify password/read-only fields and tab focus.

The opt-in NATIVEIME_DISPOSABLE_REGISTRATION_TEST exercises actual COM and TSF profile registration, profile description lookup, CoCreateInstance and unregister on a disposable Windows CI runner. It does not activate or change the default profile. NativeIME.EngineSupervisor.exe is an explicitly launched test supervisor; it starts the sibling EngineService, uses a Job object for child lifetime, retries at most three consecutive abnormal exits, and responds to Ctrl+C. No registry startup or scheduled task is created. Interactive keyboard/GUI validation remains separate.

## Desktop candidate (first-party binaries only)
CI produces NativeIME-DesktopCandidate-windows-x64 only after its regression tests pass. It is not an installer, does not register automatically, and is not self-contained. It excludes third-party DLLs and dictionaries pending redistribution review. Use the exact official librime Windows x64 1.13.1 runtime and schema data prepared by the existing CI workflow in an isolated Windows VM. Keep NativeIME.TSF.dll, EngineSupervisor, EngineService and DesktopLab in the same protected directory. Run the supervisor with absolute --shared, --user, --rime-dll arguments; choose an empty user data directory and keep the console open. Manually register the experimental DLL in the disposable VM, then select NativeIME without making it the default. Type into the standard edit control. Capture actual text and popup screenshots, repeat the negative cases, then unregister the DLL and stop the supervisor. Never use the candidate on a production system.

Microsoft TSF profile activation reference: https://learn.microsoft.com/en-us/windows/win32/api/msctf/nf-msctf-itfinputprocessorprofilemgr-activateprofile . The process-scoped activation API depends on an enabled profile and matching input language. A deferred activation or COM creation does not prove an active keyboard profile.

## New process-scoped TSF verifier

Run only in a disposable, interactive Windows VM with the experimental DLL manually registered and the NativeIME profile enabled, Simplified Chinese input language already selected, and the sibling EngineSupervisor/EngineService running with isolated Rime data. Close other test windows and release modifier keys / disable Caps Lock. Do not change the default input method. Start from the same protected candidate directory:
```powershell
.\NativeIME.TsfDesktopE2E.exe --isolated-desktop
```
The verifier uses ITfInputProcessorProfileMgr::ActivateProfile with TF_IPPMF_FORPROCESS only, checks GetActiveProfile, then invokes the real ITfKeystrokeMgr TestKeyDown/KeyDown on its own focused native EDIT control. It never inserts expected text directly, never injects global input, and does not register or enable profiles itself. It checks two exact Chinese commits, real TSF context readback, backspace/cancel, unhandled F2, password field pass-through and popup hiding on focus change. The original process profile is restored if it was changed. Exit 77 indicates preconditions missing, not a pass. Other nonzero exits are test failures. Exit zero is evidence for this specific host/API route only, not physical keyboard, third-party applications, DPI, visual or performance acceptance. Preserve console logs and capture actual popup screenshots separately. The standard CI compiles this verifier but does not execute it. CMake opt-in NATIVEIME_INTERACTIVE_DESKTOP_TEST is available only for prepared interactive VM runs.

## Native session launcher
Use the first-party experimental candidate in a prepared isolated Windows VM. With the experimental profile already registered/enabled and the input language set to Simplified Chinese, run:
```powershell
.\NativeIME.Session.exe --desktop-check --shared "C:\lab\shared" --user "C:\lab\isolated-user" --rime-dll "C:\lab\runtime\rime.dll"
```
Replace sample paths with the actual isolated data and official runtime paths. The launcher starts its sibling supervisor, waits for an owned real engine to return a known candidate, invokes the verifier and stops only its own supervisor/engine when finished. --engine-only-check exercises startup and shutdown without a desktop; --run keeps the session running until Ctrl+C. No automatic registry, language/profile or login-startup modifications. A pre-existing service is not adopted or killed. The explicit desktop-check mode is for isolated test machines only. CI runs an independent non-mutating --preflight-only probe; exit 77 is a prerequisite block, not a functional pass. Production session startup and installation integration are still pending.
