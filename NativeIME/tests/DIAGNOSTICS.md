# NativeIME diagnostics (experimental)
Windows native GUI, no browser or network. Capture is off until Start, limited to 30 minutes, and stops on normal close. Counters are aggregated in a per-logon shared memory mapping with a zero-wait writer lock; contention can drop samples. No user text, Pinyin, raw keystrokes, passwords, clipboard, paths, window titles or screenshots are captured. No per-event timeline yet. Data is not persisted until user exports a JSON report; inspect before sharing. The same-logon mapping is not a security boundary against malicious same-user code. Use only in an isolated lab.
1. Open NativeIME.exe, the product's native main window. On General, Start Engine uses the sibling private Session helper and prepared shared/ and runtime/rime.dll directories. It uses isolated LocalAppData/NativeIME/experimental-rime data. No automatic installation or profile changes. The first-party candidate still lacks those third-party files.
2. Choose the built-in Diagnostics and Testing page; click Start capture, then Self-check. Navigation preserves the same capture session. The self-check tests a fixed known Rime candidate and desktop prerequisites, not actual TSF input.
3. On a prepared isolated Windows desktop only, click the desktop TSF verification button or manually test native text controls. Stop capture and export JSON.
4. Send the exported file after reviewing it. -1 = not run, 0 = pass, 77 = blocked; other codes fail. IPC mean duration is not key-to-candidate latency. CPU/RAM sampling, ZIP packaging, raw event timeline and production deployment are pending. The prior standalone diagnostics target has been removed. The internal TSF verifier is still an opt-in lab helper. Main UI smoke checks in-process child ownership and navigation; it is not interactive GUI acceptance. Third-party runtime and data are not included in first-party candidate. Do not set experimental IME as default.

## Concurrent product and diagnostics development
The NativeIME main app embeds diagnostics. Capture now samples NativeIME.exe process CPU (one-core normalized) and working-set memory at 1-second intervals, bounded to 1,800 samples; the report is a ZIP32 archive with summary.json and performance.csv. CPU is the UI process only, not total engine/service/system CPU. IPC latency is separate from end-to-end candidate latency; candidate latency histogram is recorded in the summary. No user text, key values, window titles or paths are collected. Manual experimental mode switch is Ctrl+Shift+F12, only for a supported writable standard edit control with no active composition; secure and unknown controls pass through. Shortcut conflicts and actual TSF behaviour require interactive desktop validation.
